# 案例 009 · OpenBiliClaw：自媒体 Agent 不应只会“写”，还要持续发现内容

## 结论先行

对自媒体场景，真正有价值的 Agent 不是“输入主题 → 生成一篇文案”，而是形成长期闭环：

```text
用户画像 / 内容偏好
        ↓
跨平台信号采集
        ↓
主动发现候选内容
        ↓
筛选 / 解释为什么值得看
        ↓
进入内容库
        ↓
选题 / 研究 / 创作
        ↓
用户反馈反哺画像
```

OpenBiliClaw 是目前 DSH 社区里最值得持续跟踪的自媒体/内容发现案例之一。

## 一、项目解决了什么问题

OpenBiliClaw 的定位不是“内容生成器”，而是本地优先的跨平台内容发现 Agent。

它覆盖 B 站、小红书、抖音、YouTube、X、知乎、Reddit、微博以及开放 Web，并把跨平台行为、反馈和对话积累成用户画像，再用画像主动找内容。

对自媒体创作者而言，这种架构的价值在于：

- 把“刷平台找灵感”变成可持续的数据输入；
- 把不同平台割裂的兴趣信号统一起来；
- 把一次性选题变成长期选题资产；
- 把“喜欢 / 不喜欢 / 没价值”变成下一轮推荐的训练信号。

## 二、最值得借鉴的 DSH 设计

OpenBiliClaw 主项目和 DSH 插件是分开的：

```text
OpenBiliClaw Core
  ├─ 本地后端
  ├─ 用户画像
  ├─ 内容发现
  ├─ 内容库
  └─ 推荐/学习逻辑

DSH Plugin
  ├─ UI 常驻入口
  └─ Agent Bridge Tools
```

其 DSH 插件在界面中提供推荐、内容库、对话、画像、设置等入口，同时注册 Agent Bridge 工具，让 DSH Agent 可以读取推荐、回答探测问题并把反馈写回学习闭环。

这个边界非常值得我们复制：

> **复杂业务能力独立运行；DSH Plugin 负责把 UI 与 Agent Tool Bridge 接入，而不是把整个业务系统塞进 DSH Core。**

## 三、对 Laoli Content Agent 的直接启发

未来自媒体工作台不应该只有：

```text
选题 → 写脚本
```

更合理的 V1/V2 演进是：

### V1：内容研究工作台

```text
热点/关注源
    ↓
候选内容池
    ↓
AI 摘要 + 价值判断
    ↓
收藏 / 忽略 / 继续研究
    ↓
选题卡
```

### V2：个人内容画像

不仅记录“看过什么”，而应记录：

- 哪些选题最终拍了；
- 哪些内容数据表现好；
- 哪些标题有效；
- 哪种结构容易产出；
- 哪些领域虽然热门，但不适合账号。

形成“创作者画像”，而不是泛用户画像。

### V3：生产闭环

```text
发现
→ 研究
→ 观点
→ 脚本
→ 多平台版本
→ 发布数据回收
→ 复盘
→ 更新选题权重
```

## 四、不应该照抄的地方

OpenBiliClaw 重点是“个人内容推荐”，而我们的目标是“内容生产”。因此不宜直接复制：

- 过重的心理画像体系；
- 为推荐本身设计的大量用户兴趣层；
- 把“让用户刷得更爽”当作最终目标。

Laoli 场景的最终评价指标应该是：

```text
选题价值
+ 产出效率
+ 内容质量
+ 发布表现
+ 可复用资产积累
```

## 五、研发建议

如果后续做 Laoli Content Workspace，建议沿用这种结构：

```text
外部内容发现服务 / 数据抓取能力
        ↓
统一 Content Item / Topic Card
        ↓
DSH Tools
        ↓
Content Agent
        ↓
DSH UI Plugin
```

UI 展示内容池、选题、研究状态和产物；真正的抓取、画像、检索不需要全部写进前端插件。

## 六、判断

这是一个值得列入“一级持续跟踪项目”的社区案例。

它真正证明的不是“DSH 可以接一个推荐系统”，而是：

> **一个成熟的个性化业务系统，可以通过 UI Plugin + Agent Bridge Tool 的方式接入 DSH，使 DSH 成为统一智能工作入口，而不必成为业务系统本体。**

这条模式可以迁移到自媒体、PPT、政务方案、知识工作台。
