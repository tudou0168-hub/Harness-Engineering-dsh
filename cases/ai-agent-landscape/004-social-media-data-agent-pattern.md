# 自媒体数据智能体：从“写文案”升级为“数据驱动内容生产”

## 结论先行

今天最有价值的新发现，不是又多了一个“帮你写小红书”的 Agent，而是 DSH 社区已经出现了两类可以直接拼起来的能力：

1. **内容生产工作台**：把选题、研究、文案、图片、音频、视频、审批、项目与任务统一进 DSH；
2. **多平台数据技能包**：把抖音、小红书、快手、B站、公众号、视频号、微博、YouTube、TikTok 等数据抓取与分析能力装进 DSH。

这意味着后续自媒体 Agent 不应定位为“文案助手”，而应定位为：

```text
数据发现 → 选题判断 → 内容研究 → 文案生成 → 素材生成 → 人工确认 → 发布准备 → 数据反馈
```

## 案例 A：Beav Creator

项目：`Jamailar/beav-deepseek-harness`

定位：面向小红书与社媒运营的 DSH 插件，覆盖：
- 选题 / 趋势研究
- 知识管理
- 文案
- 封面与图文图片
- 音频
- 短视频
- 多阶段内容生产
- workspace / project / task / approval / artifact

### 值得借鉴

#### 1. 把内容生产当“项目”，不是一次聊天

最关键的不是模型会写，而是它暴露了：
- workspace
- project
- task
- approval
- verified artifact

这对我们的自媒体 Agent 很重要。真正长期运营需要“内容资产、素材、版本、审批、产物、历史效果”，聊天记录本身不够。

#### 2. “审批”应该是流程本体

选题、标题、脚本、封面、成片，不应全部自动流过去。高价值内容至少要保留：
- 选题确认
- 成稿确认
- 视觉确认

这一点和 PPT Production 的 Pioneer / 用户确认机制高度一致。

### 不建议直接照搬

不要一开始就做完整内容 SaaS。我们更适合先做一个 **Laoli Content Workspace**：
- 今日选题
- 资料卡
- 3 个平台文案
- 脚本
- 素材
- 历史内容
- 数据反馈

先验证真实生产闭环，再扩展音视频自动化。

## 案例 B：RedFox DSH Skills

项目：`redfox-data/redfox-community-dsh`

其价值在于已经把 100+ 个社媒数据能力封装成 DSH 原生 skill，包括：
- 抖音：搜索、热榜、评论分析、账号订阅等
- B站：搜索、下载、评论分析、关键词账号发现
- 快手、微博
- YouTube、TikTok、Instagram、X
- 多平台文案改写
- 违禁词检查
- 去 AI 味
- 图片 / 视频生成
- 7 平台热点聚合

### 值得借鉴

这给我们一个明确架构：

```text
采集能力 = Skill / Tool
内容方法 = Skill / Prompt
项目状态 = Workspace / 文件
用户操作 = UI
```

不要把“抓热点、写文案、做图、做视频、项目管理”全部塞进一个巨型 Prompt。

## 对 Laoli Content Agent 的建议架构

### 第一层：Data Skills

负责：
- 热点
- 搜索
- 评论
- 竞品
- 账号
- 平台趋势

### 第二层：Research Agent

负责：
- 找事实
- 找案例
- 提炼受众痛点
- 判断选题价值

### 第三层：Content Skill

负责：
- 视频号
- 抖音
- 小红书
- 公众号

同一信息，不同平台独立适配，不做简单改写。

### 第四层：Workspace UI

展示：
- 待研究
- 候选选题
- 正在生产
- 待确认
- 已发布
- 数据复盘

## 建议的第一个最小产品

不要直接做全自动发布。

先做：

```text
输入：一个领域 / 关键词
↓
自动抓最近热点、评论和典型内容
↓
生成 5 个选题卡
↓
用户确认 1 个
↓
生成三平台标题 + 内容框架 + 短视频脚本
↓
沉淀到项目文件
```

这比“自动每天发内容”更值得先验证。
